## What was tested

After completing the v0.3 noise-reduction and engine-perception-port plans, we ran real-model benchmarks to find the current ceiling before adding rlmlocal substrate. A deterministic security scanner seeds RGI with grounded findings so small local models can focus on verification rather than discovery.

## Key fix during this run

`rgi/tools/security_scan.py` was extended to detect the four textbook vulnerability classes that synthetic benchmarks exercise but the original scanner missed:

- SQL injection (f-strings / `.format()` in SQL)
- Path traversal (`os.path.join(..., *filename)`)
- Weak crypto (`hashlib.md5`, `hashlib.sha1`)
- Command injection (`os.system("..." + user)` and `subprocess.*(shell=True)`)

This fix changed the outcome from a falsification to a clear win.

## Engineering verdict

The engine is hardened to its current ceiling on these small targets:

- Findings are normalized, deduplicated, grounded, and filtered.
- The verification gate challenges ungrounded claims.
- The perception layer builds a real module/function/import graph.
- The deterministic scanner seeds obvious vulnerability classes so recursive spawning is not left to discover them from scratch.

The remaining frontier is scale and model capacity: larger real codebases (C2 targets) and cross-file vulnerability chains. Those are the next experiments, not more engine plumbing.
